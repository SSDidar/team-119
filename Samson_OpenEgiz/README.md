# САМСОН — цифровой карьер на OpenEgiz

Пространственный цифровой двойник открытого карьера: восемь 60-тонных КАМАЗ-65805 «Самсон», два экскаватора, дробильный комплекс, спиральный съезд, диспетчер и сценарии «что если». Актуальные состояния хранятся в Eclipse Ditto, телеметрия проходит через MQTT, история сохраняется в InfluxDB и доступна в Grafana.

**Запуск полного решения: `make samson`. Интерфейс: <http://localhost:8088>.**

## 1. Запуск с нуля

Нужны Linux или macOS, Git, Make, Docker с Compose v2.20+ и не менее 6 ГБ памяти для Docker. На Windows используйте Ubuntu 24.04 в WSL2 — команды выполняются в терминале Ubuntu, не в PowerShell.

```bash
git clone https://github.com/SSDidar/team-119.git
cd team-119/Samson_OpenEgiz
make samson
```

Первая команда сама создаёт локальные пароли, собирает образы, запускает OpenEgiz, регистрирует 13 двойников, включает симулятор и интерфейс. Ручная настройка, ключи и внешние сервисы не нужны. Первая загрузка образов занимает несколько минут.

После запуска:

- диспетчерский 3D-интерфейс — <http://localhost:8088>;
- Grafana — <http://localhost:3000>, логин и сгенерированный пароль выводит команда запуска;
- Ditto API — <http://localhost:8080/api/2>;
- MQTT — `localhost:1883`.

Проверка и остановка:

```bash
make samson-check   # тесты, сборка UI и проверка live-ответа OpenEgiz
make smoke          # проверка контура OpenEgiz: MQTT → Ditto → InfluxDB → Grafana
make ps             # состояние контейнеров
make logs S=mine-simulator
make logs S=mine-ui
make down           # остановить всё, сохранив данные
```

`make clean` дополнительно удаляет данные и сгенерированные пароли. Если порт 8088 занят, задайте `SAMSON_UI_PORT=8090 make samson` и откройте порт 8090.

## 2. Запуск в VS Code

1. Установите Docker Desktop и запустите его. На Windows включите WSL2 integration для Ubuntu 24.04.
2. В Ubuntu выполните `sudo apt update && sudo apt install -y make git`.
3. Откройте VS Code → **File → Open Folder** и выберите корень репозитория. На Windows сначала используйте **WSL: Connect to WSL**, затем откройте папку в Linux-домашнем каталоге.
4. Откройте **Terminal → New Terminal** и выполните `make samson`.
5. Дождитесь строки `Samson UI: http://localhost:8088` и откройте адрес в браузере.
6. Перед сдачей выполните `make samson-check` и `make smoke`.

Для разработки только интерфейса без Docker:

```bash
npm install
npm run dev          # http://localhost:5173
npm test
npm run build
```

Без работающего backend интерфейс честно переключается на **«ДЕМО-ТРАССА · OFFLINE»**. Это заранее рассчитанные кадры того же Python-движка, а не второй браузерный симулятор и не подмена OpenEgiz. В полном запуске индикатор показывает **«OPENEGIZ · DITTO»**.

## 3. Как увидеть решение

1. Вкладка **«Что если»** → выберите «Обвал на уступе», «Ливень на съезде», «Отказ ЭК-02» или «Резерв +2 машины».
2. Наблюдайте скорость, очереди, производительность, перемещение техники и состояние связанных двойников.
3. Кнопки **«Карьер»**, **«Сверху»**, **«Забой»**, **«Дробилка»** меняют ракурс. «Сверху» лучше всего показывает непрерывную спираль и встречные полосы.
4. Выберите машину щелчком в 3D или в списке слева: откроются её фактические значения Ditto.
5. Снять воздействие можно кнопкой **«Снять ограничение»**. **«Сброс»** после подтверждения возвращает базовую смену.
6. **«Архитектура»** в шапке объясняет поток данных и расположение кода. **«Экспорт JSON»** сохраняет текущий snapshot.

## 4. Где лежат агенты и двойники

| Путь | Назначение |
|---|---|
| `mine/simulator/engine.py` | `TruckAgent`, `ExcavatorAgent`, `CrusherAgent`, `DispatcherAgent`; производственный цикл, очереди, отказы, топливо и KPI |
| `mine/simulator/geometry.py` | Спираль, X/Y/Z, курсовой угол по касательной, кривизна, уклон и раздельные полосы |
| `mine/simulator/main.py` | MQTT publisher, HTTP API сценариев, экспорт офлайн-трасс |
| `mine/setup_twins.py` | Идемпотентное создание 13 Things в Ditto |
| `mine/twins.json` | Начальные документы двойников для просмотра и разработки |
| `mine/ui/server.mjs` | Серверный шлюз: читает Ditto и передаёт snapshot в UI, пароль в браузер не попадает |
| `mine/ui/components/MineScene.tsx` | Three.js: уступы, спиральная дорога, техника, камеры и выбор объектов |
| `public/traces/*.json` | Пять офлайн-трасс, экспортированных тем же движком |
| `tests/` | Проверки геометрии, детерминированности, сценариев и трасс |

Создаются 13 двойников в namespace `org.openegiz.samson`:

- `mine-01` — карьер и сменные KPI;
- `road-01` — состояние съезда;
- `crusher-01` — дробильный комплекс;
- `excavator-01`, `excavator-02` — два забоя;
- `truck-01` … `truck-08` — восемь самосвалов.

В 3D присутствуют 11 единиц техники: 8 самосвалов, 2 экскаватора и дробилка. Карьер и дорога — пространственные объекты сцены и отдельные Ditto-двойники.

## 5. Поток данных

```text
Python agents → MQTT/Ditto Protocol → Eclipse Ditto → server.mjs → React + Three.js
                                      ↓
                              Telegraf → InfluxDB → Grafana
```

Симулятор отправляет `modify` на `/features`. UI не обращается к симулятору за основными значениями: серверный шлюз читает актуальные Things из Ditto и только дополняет их служебными полями сценария. Команды сценариев идут обратно через HTTP API симулятора.

## 6. Откуда берутся значения

Реальные датчики и производственная история не используются. Все значения **синтетические и детерминированные**, зерно генератора — `65805`. Начальные условия и правила заданы в `mine/simulator/engine.py` и `geometry.py`.

- грузоподъёмность — 60 т, модель КАМАЗ-65805 «Самсон»;
- ковш — 12 т, пять проходок до полной загрузки, цикл ковша — 30 с;
- разгрузка — 55 с; план — 2400 т/ч; номинал дробилки — 3000 т/ч;
- пять уступов по 12 м, глубина 60 м, расчётный уклон спирали — 7,1%;
- скорость ограничена кривизной, уклоном, состоянием дороги, дистанцией, разгоном и торможением;
- топливо зависит от массы, уклона и сопротивления качению;
- содержание меди — заданная модель распределения, не лабораторные пробы.

Это инженерные допущения демонстрационного рудника, а не паспортные характеристики конкретного предприятия. Внешние наборы данных не загружаются; сетевые данные при запуске нужны только для Docker/NPM-зависимостей. Модель не предназначена для управления реальной техникой.

## 7. Проверки и ограничения

`npm test` проверяет пять трасс, 13 уникальных двойников, 61 кадр на сценарий, различия сценариев, непрерывный подъём, уклон, раздельные полосы, встречный heading, детерминированность, скорость, массу, резерв и отказ экскаватора.

В среде подготовки проекта выполнены unit/integration-тесты движка и трасс, production-сборка и браузерная проверка desktop/mobile, сценариев, паузы, модальных окон и движения по спирали. Полный Docker-контур перед конкурсной отправкой необходимо ещё раз проверить на машине с Docker командами `make samson`, `make samson-check`, `make smoke`; в среде подготовки Docker отсутствовал.
